# CVBuilder — რეზიუმეს ონლაინ კონსტრუქტორი

ქართულენოვანი, უფასო სასწავლო ვებგვერდი: შეავსე ინფორმაცია, აირჩიე დიზაინი და დაბეჭდე რეზიუმე PDF-ად.

ავტორი: **ნინო შარაშიძე**. პროექტი ინდივიდუალურია.

## მიმდინარე მდგომარეობა

ეს ახალი ვერსია დროებით `rebuild/` საქაღალდეშია. არსებული ძირითადი ვერსია არ შეცვლილა. მისი ჩანაცვლება მოხდება მხოლოდ მფლობელის აშკარა თანხმობის შემდეგ, ცალკე ცვლილებით. მიმდინარე სამუშაო branch: `feature/cvbuilder-rebuild`.

## ტექნოლოგიები და გაშვება

HTML5, CSS3 (Grid/Flexbox, media queries და print), ვანილა JavaScript ES modules და localStorage. არ გამოიყენება React, ბიბლიოთეკები, npm ან აწყობის სისტემა. საიტის გასაშვებად Node.js საჭირო არ არის.

```sh
git clone https://github.com/lapetiteNea/cvbuilder.git
cd cvbuilder
git switch feature/cvbuilder-rebuild
python3 -m http.server 8000
```

გახსენი `http://localhost:8000/rebuild/`. ალტერნატივაა VS Code Live Server. `file://` გზით მოდულები ვერ ჩაიტვირთება.

## შესაძლებლობები

- ექვსი გვერდი: მთავარი, რედაქტორი, შაბლონები, ჩემი რეზიუმეები, რჩევები, კონტაქტი.
- ფორმის შევსებისას პრევიუს განახლება; სახელის, ელფოსტისა და ტელეფონის შემოწმება.
- გამოცდილების, განათლებისა და უნარების დამატება/წაშლა; სამი სექციის გადაადგილება.
- სამი შაბლონი, აქცენტის ფერი და უნარების ჩამონათვალიდან ავტოშევსება.
- რამდენიმე რეზიუმეს შენახვა, ძიება, ხელახლა გახსნა და განახლება; წაშლის დადასტურება.
- მხოლოდ რეზიუმეს ბეჭდვა. PDF: „ბეჭდვა / PDF“ → Save as PDF → A4; გამორთე ბრაუზერის headers/footers.
- მობილური მენიუ, კლავიატურის ფოკუსი, მონიშნული შეცდომები, დახმარების აკორდეონი.

მონაცემები ინახება მხოლოდ ამ მოწყობილობის ბრაუზერში. ძველი საიტის `cvbuilder_data` ჩანაწერი არ იცვლება და ავტომატურად არ გადმოდის. ახალი ვერსია იყენებს ცალკე `cvbuilder_rebuild_v1` გასაღებს. ავტომატური შენახვა არ არის: გამოიყენე „შენახვა“. შენახვის გარეშე გასვლისას ბრაუზერი გაფრთხილებას აჩვენებს. ბრაუზერის მონაცემების წაშლა რეზიუმეებსაც წაშლის. კონტაქტის ფორმა დემოა და შეტყობინებას არსად აგზავნის.

## სტრუქტურა

- `pages/`: რედაქტორი და დანარჩენი გვერდები.
- `css/`: საბაზო სტილები, განლაგება, კომპონენტები, შაბლონები და ბეჭდვა.
- `js/model.js`: მონაცემთა მოდელი, შემოწმება და სექციების რიგი.
- `js/storage.js`: შენახვა, განახლება და წაშლა.
- `js/templates.js`: უსაფრთხო DOM პრევიუ (`textContent`).
- `js/editor.js`, `js/pages.js`, `js/main.js`: გვერდების ინტერაქცია.
- `tests/`: ლოგიკის ავტომატური ტესტები.
- `docs/`: შემოწმების ჩანაწერი და GitHub Pages-ის ინსტრუქცია.

## ტესტირება

ავტომატური ტესტებისთვის სურვილისამებრ გამოიყენე Node.js 22 ან ახალი:

```sh
node --test rebuild/tests/core.test.mjs
```

გაშვებული შემოწმებები და დარჩენილი ხელით შესამოწმებელი საკითხები აღწერილია [ტესტირების ჩანაწერში](docs/TESTING.md). Chrome/Firefox-ის სრული შემოწმება და Lighthouse ჯერ შესასრულებელია; მათი შედეგები არ არის გამოგონილი.

## GitHub-ზე პროცესის აღბეჭდვა

ისტორიაში რეალური სამუშაო ეტაპები ცალკე commit-ებად ინახება: ინიციალიზაცია, გვერდები, დიზაინი, ფუნქციები, ტესტები და დოკუმენტაცია. თითო ახალი ამოცანისთვის გამოიყენე `feature/<აღწერა>`, შეცდომისთვის `fix/<აღწერა>`, დოკუმენტაციისთვის `docs/<აღწერა>`. commit ფორმატი: `feat: add education fields`.

Push-ის შემდეგ გახსენი PR `main`-ისკენ, აღწერე შედეგი და შემოწმებები; ნახე Files changed. გაერთიანებამდე შეამოწმე საიტი და კონსოლი. ამ PR-ის გაერთიანება დაამატებს მხოლოდ `rebuild/` ვერსიას და არ ჩაანაცვლებს მთავარ გვერდს. ძველი ფაილების წაშლა/ჩანაცვლება ცალკე თანხმობას მოითხოვს.

გამოქვეყნების ზუსტი ნაბიჯები: [GitHub Pages](docs/PUBLISHING.md).
